Security Posture

Does compliance = security?
Just because a system passes all its compliance checks doesn't mean it's safe. A system can follow every rule in the book but still have unpatched software with known vulnerabilities. This page cross-references your compliance controls (the rules) with real-world vulnerabilities (CVEs) to show you where the gaps are. Each system falls into one of four categories below.
-
Secure & Compliant
Following the rules AND no known vulnerabilities. The ideal state.
-
Compliant but Vulnerable
Passing audits, but exposed to known vulnerabilities that no control covers.
-
Non-compliant + CVE Risk
Highest priority. A security rule that protects against a real vulnerability is failing.
-
Non-compliant (No CVE Link)
Compliance failures exist but aren't tied to a known vulnerability. Still needs attention.

Fix These First

These are your highest-priority items. In each case, a security rule exists specifically to protect against a known vulnerability — but that rule is currently not being followed. Until these are fixed, the vulnerability has no protection.

How to Read This Graph

This graph shows how compliance failures and vulnerabilities connect across your systems.

■ Products
Top-level groupings like "OpenShift" or "RHEL" that contain one or more systems.
■ Systems
Click a system box to expand it and see its components, violations, and CVEs.
▲ Violations
Red triangles = a security rule is currently being broken on this system.
■ Components
Software packages installed on the system (from SBOM data).
● CVEs
Known vulnerabilities, color-coded: green = mitigated, red = unmitigated, amber = fix available.
■ Critical Gaps
Amber boxes appear when a CVE has a mitigating control but that control is failing. Fix these first.

Drift Timeline

What is Drift?

Drift happens when a system that was previously following the rules stops following them. For example, someone might change a configuration that makes a system non-compliant. This timeline shows when and where that happened.

● Passing — System was compliant
● Failing — Something changed, now non-compliant
● Who/What — The user or process that triggered the change
